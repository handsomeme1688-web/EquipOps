# EquipOps Web

EquipOps 智能设备运维平台的完整前端。项目位于 `equipops-api/equipops-web`，与后端代码完全隔离。

## 已实现界面

- 登录、注册与会话恢复
- 运营总览：设备健康、工单效率、SLA 风险、RepairMind 洞察
- 设备台账：组合筛选、设备详情、安全附件、维修历史、新建设备
- 维修工单：7 状态工作流、看板、详情、流转动作、并发与幂等提示
- RepairMind：对话、引用来源、安全警告、受控工具调用与报修确认
- 组织与权限：账户、部门、角色、权限矩阵
- 审计与监控：服务健康、请求指标、安全事件、traceId 审计记录
- 51 天建设进度：当前 Day 12、阶段完成度、未来 5 天任务与接口接通状态

## 运行

要求 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

浏览器打开开发服务器输出的本地地址。

生产构建：

```bash
npm run build
```

完整验证：

```bash
npm test
```

仅检查 EquipOps 业务前端类型（排除模板自带的 Worker 基础设施）：

```bash
npm run typecheck
```

## 后端连接

开发环境默认把浏览器的 `/backend/*` 请求代理到 `http://127.0.0.1:8080/*`，因此不需要修改 Spring Boot 的跨域配置。

当前真实接入：

| 前端能力 | 后端接口 |
|---|---|
| 登录 | `POST /auth/login` |
| 注册 | `POST /auth/register` |
| 当前用户与权限 | `GET /auth/me` |
| 设备分页 | `GET /devices/page` |
| 设备详情 | `GET /devices/{id}` |
| 创建设备 | `POST /devices` |
| 修改设备 | `PUT /devices/{id}` |
| 删除设备 | `DELETE /devices/{id}` |

说明：需求文档中的最终基础路径是 `/api/v1`，但当前 Controller 尚未配置该前缀。前端以当前可运行代码为准；后续统一前缀时，只需调整代理重写或 `NEXT_PUBLIC_API_BASE_URL`。

## 页面路由

| 页面 | 地址 |
|---|---|
| 登录 | `/login` |
| 注册 | `/register` |
| 运营总览 | `/overview` |
| 设备台账 | `/devices` |
| 维修工单 | `/work-orders` |
| RepairMind | `/assistant` |
| 账户管理 | `/organization/users` |
| 部门管理 | `/organization/departments` |
| 角色权限 | `/organization/roles` |
| 审计监控 | `/audit` |
| 建设进度 | `/roadmap` |

访问根地址 `/` 会跳转到 `/login`。登录成功或进入预览模式后会进入 `/overview`；未登录直接访问工作台地址时会回到 `/login`。

### 注册与手机号验证

- 手机号为必填项，必须先完成验证码校验才能提交注册。
- 当前后端还没有短信验证码发送与校验接口，因此注册页采用明确标识的“本地开发验证码”：点击发送后，验证码会显示在页面上，便于现阶段联调。
- 后续接入短信服务时，只需把前端的发送与校验动作替换为真实接口；正式环境必须由后端保存、校验验证码并限制发送频率。
- 注册接口即使返回访问令牌，前端也不会保存。注册成功后会回到登录页，用户必须使用用户名和密码重新登录。

## 预览模式

登录页可直接选择“进入完整预览模式”。它不会写入后端，适合：

- 后端未启动时检查全部页面
- 演示 Day 15 以后才会实现的工单、审计和 AI 能力
- 逐日开发时对照最终产品形态

已实现的真实接口优先使用真实数据；尚未实现的模块集中在前端数据层中，后续只需替换对应请求函数，无需重做界面。

## 环境变量

复制 `.env.example` 为 `.env.local` 后可调整：

```env
NEXT_PUBLIC_API_BASE_URL=/backend
NEXT_PUBLIC_ENABLE_MOCK=true
```

若要改变本地后端地址，可在启动前设置服务端环境变量：

```env
EQUIPOPS_API_ORIGIN=http://127.0.0.1:8080
```

## 设计约束

- 所有按钮显隐会读取 `/auth/me` 返回的权限码，但最终授权必须由后端完成。
- 设备状态不在编辑表单中手动修改，状态应由后续工单流程驱动。
- AI 报修只生成草稿，必须经过用户显式确认才可落库。
- 文件下载必须由后端在返回文件流之前校验设备数据范围。
- 创建类请求的幂等不能只依赖 Redis，仍需数据库唯一约束兜底。
